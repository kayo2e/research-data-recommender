# 나라장터 자체입찰 공고 법령 위반사항 모니터링 AI 경진대회

Dacon: https://dacon.io/competitions/official/236754 (조달청 주최). 가영 개인 참가.

- 대회 기간: 2026.08.26 ~ 2026.09.30 10:00 (팀 병합 마감 09.23, 제출 마감 09.29)
- 상금 4,200만 원, private 리더보드 상위 15팀 → 정량 80% + 정성(근거문구 품질) 20%로 최종 7팀

## 과제

입찰공고 1건(공고문 + 첨부 문서 + 나라장터 등록 meta)을 읽고 24개 검토 항목(v1~v24) 각각의
위반 여부(0/1)와 근거 문구(e1~e24)를 판정. 제출은 `output/submission.csv`(49열: id, v1~v24,
e1~e24) 코드 제출(`submit.zip` = `script.py` + `requirements.txt` + `model/`(선택, 정적 자산만)).

## 핵심 제약 (위반 시 실격/무효)

- **고정 LLM 필수, 파인튜닝·LoRA 전면 금지**: `google/gemma-4-26B-A4B-it`. 평가 서버가
  `PPS_MODEL_DIR`에 가중치를 이미 준비해두고 `script.py`가 vLLM offline API로 인프로세스 로드.
  모델 파일은 제출물에 넣지 않는다.
- **제출 코드는 공고마다 고정 모델을 1회 이상 정상 호출해야 함** — 모델 호출 없이 규칙만으로
  만든 제출물은 무효.
- **공식 라벨 학습 데이터 없음**: `train_unlabeled.jsonl.gz`(2만건, 무라벨) + `dev.jsonl.gz`/
  `dev_labels.csv`(200건, 라벨 예시 — 항목당 위반 5~8건 + 정상 112건). 자가 라벨링 전면 허용
  (수작업/규칙/모델 무관), 단 **외부 LLM에는 대회 제공 자료만 입력 가능**(웹 검색·외부 문서
  결합으로 원문 조회하거나 외부 데이터 끌어오는 것 금지). 라벨 생성 단계에서는 상용 API 포함
  외부 LLM 사용 가능(추론 단계는 고정 모델만). 생성 라벨 공유는 코드공유 게시판 전체공개만
  허용(팀 간 사적 공유 금지). 수상 시 라벨 생성 코드·프롬프트 재현 검증 대상.
- **평가 서버 인터넷 차단** — 법령 검색(RAG)도 `data/법령패키지/`(법령/행정규칙 23건 txt +
  중기부고시 hwpx/csv)로만 구성. 대회 기간 중 법령 개정 미반영(스냅샷 고정).
- **`if __name__ == "__main__":` 필수** — 없으면 vLLM 특성상 즉시 실패(흔한 실수 1위).
- **경로 하드코딩 금지** — 환경변수(`PPS_DATA_DIR`/`PPS_OUTPUT_DIR`/`PPS_MODEL_DIR`)로.

## 로컬 폴더 구조 (open.zip 압축 해제본)

```
baseline/script.py, requirements.txt   # 공식 베이스라인 — 배포 로직 그대로, 건드리지 않는 한 항상 유효한 제출물
data/test.jsonl.gz                      # 로컬용 샘플 10건 (평가 서버에서는 실제 1,853건으로 교체)
data/항목표.json                        # 24개 항목: 항목명·부재탐지 여부·국가/지방계약법 근거조문·비고
data/정답스키마_디코딩.json             # 제약 디코딩(vLLM structured outputs)용 JSON 스키마
data/법령패키지/                        # 법령 원문 스냅샷 (RAG는 이것만 사용)
dev.jsonl.gz + dev_labels.csv           # 라벨 예시 200건 — 자가 채점 기준으로 사용 가능
train_unlabeled.jsonl.gz                # 무라벨 2만건 — few-shot 채굴/자가 라벨링용
sample_submission.csv                   # 제출 형식 예시 10행
submit.zip                              # 현재 제출물(공식 베이스라인 그대로, script.py+requirements.txt만)
```

로컬 실행: `python3 baseline/script.py --mock` (모델 없이 입출력 흐름·형식만 확인, macro-F1
안 나옴 — 실제 채점은 evaluation 서버가 `--mock` 없이 실행해 진짜 Gemma로 판정).

## 24개 항목 — 그룹별 요지 (dev 200건 분석, 2026-09-13)

- **v2~v8 (실적·지역 제한)**: "고시금액" 임계값과 `meta.입찰추정가격`/`배정예산금액` 비교가
  핵심. 고시금액 실제 수치를 `법령패키지`에서 찾아 system prompt에 상수로 박아주지 않으면
  이 7개 항목은 사실상 랜덤에 가까움 — **최우선 개선 지점**.
- **v13~v18 (중기업·소상공인 제한)**: 금액 구간(1억 미만/1억~고시금액/고시금액 이상)별로
  소기업 vs 중소기업 vs 제한없음이 반복. v16/v18은 부재탐지형.
- **v9~v12 (중기간 경쟁제품)**: v9는 순수 텍스트 탐지(과업지시서의 특정 제조사·모델명 — 예:
  "Akron Brass 터보젯")라 임계값 의존 없이 상대적으로 쉬움. v10/v11은 부재탐지형.
- **v19~v23 (절차 요건)**: v20(SW)은 금액 구간별로 완전히 다른 규칙(부재탐지). v21은 공동수급
  지분율(기준 미만이면 위반, 3%도 걸림). v22/v23은 `meta.계약방법`이 "협상"일 때만 적용되는
  조건부 룰 — 이 필드를 프롬프트에서 명시적으로 강조해야 함.
- **v24만 성격이 다름**: 근거법령 없음. 공고서 본문 vs 나라장터 meta 값 자체의 불일치를
  점검(예산·계약방법·지역제한·업종) — 법령 위반 판정이 아니라 데이터 정합성 체크.
- **부재탐지 5항목(v10·v11·v16·v18·v20)**: "있어야 할 기재가 없는 것"이 위반 → 근거문구 항상
  빈칸(스키마에서 `null` 고정).

## 근거 문구(e열) 규약

원문 그대로의 부분문자열만 인정(요약·수정 시 무효), 500자 이하, 위반 아니면 빈칸, 수식 접두
문자(`=`,`+`,`@`) 금지, UTF-8(BOM 없음)·NFC 정규화. 리더보드 점수엔 안 들어가지만 원본이
보존돼 2차 정성평가(20%) 재료로 쓰이므로 처음부터 성실하게.

## 중요: Dacon 토크 게시판에 운영진 공식 답변 있음 (2026-09-14 확인)

- **대회 토크 게시판(`/talkboard`)에서 "v24", "지역제한여부" 등으로 검색하면 라벨/항목 관련
  질문에 DACONIO(운영진)가 직접 답변한 글들이 있다** — 새 항목을 자가 라벨링/역추론하기 전에
  먼저 토크 게시판을 검색해볼 것. 재검증에 서브에이전트 토큰을 쓰기 전에 이걸 먼저 확인했어야
  했음(교훈).
- **`dev_labels.csv`는 "실제 검토 업무 이력에 기반한 참조용 자료"이고 노이즈가 있을 수 있다고
  운영진이 명시함** — 개별 dev 예시가 항목표의 판정 기준과 안 맞아 보이면, 라벨보다 항목표
  판정 기준을 우선하라고 함. 2026-09-13에 v24를 5건의 dev 예시로 역추론하려다 계속 실패한
  이유가 이것 — 일부는 애초에 라벨 노이즈였을 가능성이 큼. **소수의 dev 예시만으로 새 규칙을
  일반화하지 말 것.**
- **v24(공고서-meta 상이) 공식 확인**: 예산·계약방법·지역제한·업종 네 축 전부 "meta가 요약하는
  결론 vs 공고서가 실제로 명시한 내용"을 비교하는 것. 예산 축은 "공고서 기재 사업예산 vs
  meta.배정예산금액/입찰추정가격" 일치 여부.
- **익명화 토큰 `[지역:rN|단위=X|광역=Y]`의 "단위=" 값이 실제 제한 범위**(운영진 확인, v6
  관련 질문 답변): "단위=기초"면 시·군·구 하나(→ v6 위반 대상), "단위=광역/특별시/특별자치시/
  도/특별자치도"면 광역 전체(→ 위반 아님). 토큰 앞뒤 평문 지명(예: "서울특별시")은 장식일 뿐,
  판정은 토큰의 "단위=" 값으로 한다 — `baseline/fewshot.py` v6에 이 파싱 규칙 반영함.
- **v1(특정기관 제한) 공식 확인**: 대학·연구기관 같은 기관명/종류 직접 지정에만 한정되지 않음
  — 법령상 근거 없이 특정 시설을 두거나 일정 규모 이상 인력·시설을 요구해 참가를 제한하는
  경우도 v1 대상(국가계약법 시행령 제12·21조/지방계약법 시행령 제13·20조 근거). v1은 아직
  few-shot 없음 — 다음에 추가할 것.

## 현재 상태 (2026-09-13 기준)

- **제출 1** (09-12, 무수정 공식 베이스라인): macro-F1 **0.2079**, 370등.
- **제출 2** (09-13, `thresholds.py` 임계값 그라운딩 추가): macro-F1 **0.2330** (+0.025, +12%).
  방향은 맞았지만 기대(0.33~0.40)보다 훨씬 작은 폭 — 임계값만으로는 부족한 항목(v15/17/18
  예외조항 등)이 많다는 신호.
- **이후 추가**(아직 제출 전, 로컬 `--mock` 검증만 완료): `baseline/fewshot.py` — v9·v12·v14·
  v15·v16·v17·v18·v19·v21·(v6/v7↔v2/v8, v11/v13↔v10 클러스터 대표)까지 few-shot 예시 확보.
  dev 200건 출처(v15/v17 일부·v19·v21)와 무라벨 2만건 자가 라벨링(원문 전체 대조, 서브에이전트
  3차 패스로 검증) 출처를 섞어 씀 — 자가 라벨링은 대회 규정상 허용(추론 단계는 여전히 고정
  모델만). `thresholds.py`에 `meta.조항호내용`(공고가 스스로 밝힌 근거 조항 — v13~v18 판정에
  임계값 계산보다 더 직접적인 신호) 강조 문구도 추가.
  - **판로지원법 시행령 제2조의2/제2조의3 정확한 구조 확정**(법령 원문 직접 대조): 1억원 미만
    구간의 법정 용어는 "소기업 또는 소상공인"(전용 정의), 1억~고시금액 구간은 "중소기업자"다.
    제2조의3 예외는 "우선조달계약 자체를 안 걸 수 있게" 해주는 것 — **예외를 인용했다고 자동으로
    위반 아님이 되는 게 아니라, 인용된 조항이 정확히 무엇을 허용하는지 확인해야 한다**(예:
    "비영리법인 참가 허용" 예외는 소기업으로 범위를 좁혀도 된다는 근거가 아님 — fewshot.py의
    v15 위반/위반아님 대조 쌍이 이 구분을 보여줌).
  - few-shot 프롬프트 텍스트(label/why)는 실제로 고정 모델이 읽는 지시문이라, 설명체가 아니라
    SYSTEM_HEAD와 같은 짧고 단정적인 규칙 문장으로 씀. 출처(자가 라벨링 여부·문서 ID)는
    `source` 필드로 분리해 프롬프트엔 안 실리게 함(재현성 기록 전용).
- **`score.py` 신규**: `dev_labels.csv` 기준 자가채점 스크립트(`python3 score.py <submission.csv>
  --by-item`) — macro-F1과 24개 항목별 F1을 로컬에서 계산. 로컬엔 GPU가 없어 실제 모델 추론은
  못 돌리지만(mock만 가능), 나중에 GPU 환경에서 돌린 결과나 실제 제출 흐름 검증에 재사용.
- 하루 1회 제출 제한 — 변경사항을 한 번에 몰아넣지 않고 하나씩 분리해서 제출해 원인 파악
  가능하게 유지하는 중 (지금까지: ①무수정 베이스라인 ②임계값 그라운딩만 → 다음: few-shot
  추가분만 분리 제출해서 효과 확인 예정).
- 코드: `narajangter-comp/baseline/{script.py,thresholds.py,fewshot.py,requirements.txt}` +
  `narajangter-comp/score.py` 전부 홈 디렉토리 repo(`research-data-recommender`)에 커밋됨(대회
  원본 데이터 파일은 제외).
